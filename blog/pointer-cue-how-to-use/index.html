Pointer Cueの基本的な使い方｜デモでポインター・クリック・範囲・ウインドウを見せる

Pointer Cueの現行macOS版で、ポインター位置のリング表示、クリック位置のフラッシュ、操作中ウインドウの強調、範囲を囲む操作を短い動画で解説します。1回の製品デモでどう組み合わせるかも紹介します。

この記事はPointer Cueの現行macOS版の基本操作を、実際の操作動画で確認するためのガイドです。製品の概要や入手方法はPointer Cueの製品ページにまとめています。ここでは、デモ中にどう使うかだけに絞ります。

このガイドの考え方

Pointer Cueは、画面に説明を書き残すよりも、デモ中の「指す・クリックする・別のウインドウへ移る・範囲を示す」という操作へ短い視覚手掛かりを足す使い方が中心です。

4つの操作を使い分ける

伝えたいこと使う操作
次にどこを見るかポインター位置をリングで示す
実際にどこを押したかクリック位置をフラッシュで見せる
複数ウインドウのうち今どれを見るか操作中のウインドウを強調する
どこまでが同じ説明の対象かドラッグして範囲を一時的な枠で囲む

すべてを常に表示する必要はありません。「今、視聴者が何を見失いやすいか」に合わせて、その場に必要な目印だけを使います。

Commandキーでポインター位置を示す

次に操作するボタンや、説明している項目へポインターを移動し、Commandキーを押すとポインター周辺にリングが表示されます。ポインターそのものを大きくするのではなく、「今ここを見てほしい」という位置を短く示す使い方です。

ボタンを指した後は、そのままクリックや入力へ進めます。説明のために別の描画モードへ切り替える必要はありません。

クリックした位置をフラッシュで見せる

左クリックが完了すると、クリックした位置に短いフラッシュが表示されます。「ポインターがどこにあったか」だけでなく、「実際にどこを押したか」を視聴者に伝えたいときに使います。

ドラッグ操作をクリックとして見せないため、ドラッグではこのクリック表示は出ません。クリックとドラッグが続くデモでも、押した場所だけを区別できます。

操作中のウインドウを強調する

複数のウインドウを開いてデモするときは、メニューバーから「Highlight Active Window」をオンにします。現在操作しているウインドウを見つけやすくし、別のウインドウへ移ると強調対象も切り替わります。

Safariから別のアプリへ移る、設定画面からログ画面へ移る、といった場面で特に分かりやすくなります。ウインドウを切り替えるたびに説明用の図形を描き直す必要はありません。

見てほしい範囲を囲む

一点ではなく、表の数行や画面の一部分をまとめて説明したいときは範囲を囲みます。初期設定ではCommandキーを押しながらドラッグして、見てほしい範囲を一時的な枠で示します。

範囲を囲む操作やショートカットの利用条件・設定は、現行の製品ページで確認できます。

1回のデモではこう組み合わせる

4つを個別の機能として覚えるより、実際のデモの流れに沿って使う方が分かりやすくなります。たとえば設定変更を見せるなら、次の順番です。

  1. 指す：次に押すボタンへポインターを置き、Commandでリングを表示する。
  2. クリックする：ボタンを押し、フラッシュで実際に操作した場所を見せる。
  3. 別ウインドウへ移る：結果を確認する画面へ切り替え、操作中のウインドウを明確にする。
  4. 範囲を示す：ログや表の該当部分だけを枠で囲んで説明する。
  5. 次へ進む：目印を残さず、次のクリックや入力へ戻る。

この流れがPointer Cueの使い方の中心です。デモの途中で「説明する時間」と「操作する時間」を分けすぎず、操作そのものを見せながら必要な場所だけを補助します。

表示を自分のデモに合わせる

メニューバーから、使う強調表示や色などをデモに合わせて調整できます。背景色や資料の内容によっては、強調表示を増やすより、必要なものだけオンにした方が見やすいこともあります。

画面共有や録画で使う場合は、本番と同じ共有方法で一度受信側・録画結果を確認しておくと、サイズや見え方を判断しやすくなります。詳細な設定項目は公式サポートで確認できます。

次に読む

画面共有・製品デモで「どこを見るか」を伝えるポインター、クリック、ウインドウ切り替え、範囲説明を「Shared Attention」というデモの流れで整理します。 ScreenBrushとPointer Cueを比較描画・注釈を残すツールと、ライブデモ中の操作を支援するツールの違いから比較します。
