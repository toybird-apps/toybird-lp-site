画面共有・製品デモで「どこを見るか」を伝える｜Shared Attentionとデモ支援

画面共有や製品デモでは、ポインターを示すだけでなく、クリック、ウインドウ切り替え、範囲説明、結果確認まで続きます。発話・見る場所・操作・結果を揃えるShared Attentionと、デモ支援の考え方を具体例で整理します。

「このボタンを押します」と話しながら、自分では正しい場所を見ている。ところが参加者側では、ポインターが小さく動いただけで、どのボタンの話だったのか分からない。画面共有や製品デモでは、操作そのものよりどこを見て、何が起きたかを共有することが難しい場面があります。

自分には見えている。相手には見えていない

操作している人は、次に触る場所をすでに知っています。画面の構造も理解しています。一方、初めて見る参加者は、説明を聞きながら「どこにあるか」「何を押したか」「どの画面へ移ったか」「結果がどこに出たか」を同時に探します。

特にSaaSの設定画面、複数ウインドウを使う製品デモ、表やログを行き来する説明では、マウスポインターを動かすだけでは、発話と操作の対応がずれやすくなります。

デモは「描く」だけではない

デモ支援を考えるとき、画面へ線や矢印を描く機能だけを見ると、実際の操作の多くが抜けます。ライブデモでは、次のようなアクションが連続します。

  • 次に見るボタンへポインターを移動する。
  • そのボタンをクリックする。
  • 別のウインドウや画面へ切り替える。
  • 数行・一部分だけをまとめて説明する。
  • 変更後の状態を確認し、次の操作へ進む。

つまり、デモ支援で重要なのは「絵を描けること」だけではなく、通常の操作を止めずに、視聴者の注意を次の場所へ運べることです。

Shared Attention：見る場所まで共有する

マルチメディア学習の研究では、重要な要素へ注意を向けるcue（手掛かり）を加えることが、情報理解を助ける場合があると報告されています。画面共有でも、文章を増やすだけでなく、話している内容と見る場所を対応させることができます。

この記事では、発話・見る場所・操作・結果を同じ流れに揃える考え方をShared Attentionとして整理します。社会認知などで使われる同名の学術概念を定義し直すものではなく、リモート説明を組み立てるための実務上の整理です。

Shared Attention = 何を説明しているかだけでなく、今どこを見てほしいか、どこを操作したかまで相手と共有すること。

30秒のデモを、注意の流れで組む

仮のSaaSで「即時通知をオフにし、その変更がログへ反映されたことを確認する」場面を考えます。30秒は説明用の目安で、最適時間を実測した数字ではありません。

時間話す内容操作視聴者に伝えたいこと
0〜5秒即時通知だけをオフにします設定画面を見せるこれから何が変わるか
5〜9秒こちらが即時通知です対象へポインターを置く次に見る場所
9〜13秒ここをオフにします一回クリック実際に操作した場所
13〜18秒次にログを確認します別ウインドウへ切り替える今見るべきウインドウ
18〜24秒この行が今回の変更ですログの数行を示す説明対象の範囲
24〜30秒通知はオフ、変更も記録されています結果で止める操作の結果

ポインター・クリック・範囲・ウインドウは役割が違う

示し方答える疑問デモでの例
ポインター位置次にどこを見るのか今回押す設定ボタン
クリック位置実際にどこを操作したのかオン／オフを切り替えた場所
操作中のウインドウ複数画面のうち今どこを見ればよいか設定画面からログ画面へ移った直後
範囲どこまでが同じ説明の対象か関連する数行、表の列
言葉なぜ見るのか、結果は何か「この変更がログへ反映されています」

これらは同じ「強調表示」ではありません。視聴者が迷っている理由に合わせて使い分けます。目印だけでは目的が分からず、言葉だけでは場所が分からないため、両方を同じタイミングへ揃えます。

目印を増やすほど伝わるわけではない

画面の文字が小さすぎるなら、ポインターだけ大きくしても解決しません。まず共有範囲や表示倍率を調整します。また、画面にすでに十分な強調があるなら、新しいリングや枠を重ねない方がよいこともあります。

Shared Attentionの目的は「エフェクトを増やす」ことではなく、参加者が発話・対象・操作・結果を対応づけられるようにすることです。

受信側で見える状態まで確認する

ローカルで見える線、ポインター、フラッシュ、文字が、会議アプリを通した後も同じ大きさ・鮮明さで見えるとは限りません。本番と同じ共有方式で、機密を含まない素材を使い、参加者側の画面を確認します。

OS、会議アプリ、共有対象を変えた場合は、その条件で再確認します。「自分の画面では見えた」と「相手に操作が伝わった」は別の確認項目です。

残す説明と、一時的に示す説明を分ける

設計図へ矢印を書き込み、番号や文章を加え、後から見返せる状態を残したいなら描画・注釈ツールが向きます。一方、クリックするボタンを数秒だけ示し、そのまま入力やウインドウ切り替えへ進みたいなら一時的な視覚手掛かりが向きます。

どちらが優れているかではなく、説明を成果物として残すのか、ライブデモの操作を追いやすくするのかで選びます。

Pointer Cueをデモ支援として使う

Pointer Cueの現行macOS版では、ポインター位置をリングで示し、クリック完了位置にフラッシュを表示し、必要な範囲を一時的な枠で囲み、操作中のウインドウを視覚的に強調できます。

重要なのは、これらを個別の「描画機能」として使うことではありません。指す → クリックする → 別ウインドウへ移る → 範囲を説明する → 次の操作へ進むというデモの流れに重ねることです。

そのためPointer Cueは、画面へ説明を書き残すツールというより、ライブデモ中の視線と操作をつなぐデモ支援ツールとして考えると役割が分かりやすくなります。
