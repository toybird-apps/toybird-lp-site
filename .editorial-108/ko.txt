# ChatGPT로 고객 답장 쓰기: 확인된 사실과 약속할 수 있는 범위부터
고객은 회의 전에 자료가 필요하지만 기술팀은 아직 장애 원인을 모릅니다. 이때 필요한 것은 복구를 장담하는 답장이 아니라, 현재 상황과 다음 연락을 분명히 알리는 첫 답장입니다.

아래 고객 메일, 내부 메모, 답장 예시는 설명을 위해 만든 가상 사례입니다. 실제 고객 문의나 AI 실행 결과가 아닙니다.

## 오후 5시와 오후 3시는 서로 다른 약속입니다
> CSV 내보내기 버튼을 눌러도 파일이 생성되지 않습니다. 오늘 오후 5시 내부 회의에 자료가 필요한데 그전까지 해결되나요? 현재 상황을 알려 주세요.

오후 5시는 고객이 자료를 필요로 하는 시각입니다. 내부에서 정한 오후 3시는 진행 상황을 연락하는 시각입니다. 둘 다 확인된 복구 시각은 아닙니다.

| 구분 | 이번 사례에서 아는 내용 |
| 확인된 사실 | 문의를 접수하고 기술팀에 조사를 요청했습니다. |
| 아직 모르는 내용 | 원인, 영향 범위, 복구 시각, 유효한 우회 방법입니다. |
| 승인된 약속 | 진전이 없어도 오후 3시까지 상황을 연락합니다. |
| 고객에게 물을 내용 | 발생 시각, 브라우저와 버전, 오류 메시지 유무입니다. |
| 승인되지 않은 내용 | 환불, 보상, 수동 자료 제공, 복구 기한입니다. |

## 답장 자료와 금지할 추측을 함께 전달합니다
업무 자료는 조직에서 허용한 AI 환경과 범위 안에서 사용하세요. 고객 이름만 지웠다고 기밀성이 사라지는 것은 아닙니다.

```text
고객에게 보낼 첫 답장을 작성해 주세요.
고객 메일과 아래 내부 메모에 있는 정보만 사용하세요.
오후 5시 회의에 자료가 필요하다는 점을 이해했음을 알리세요.
문의가 기술팀에 전달되어 조사를 요청한 상태임을 쓰세요.
복구 시각은 모르므로 오후 5시 전 복구를 약속하지 마세요.
진전 여부와 관계없이 오후 3시까지 상황을 연락한다고 쓰세요.
발생 시각, 브라우저와 버전, 오류 메시지를 질문하세요.
원인, 재설치 절차, 우회 방법, 환불 등 추가 사실이나 약속은 넣지 마세요.
제목과 본문을 작성한 뒤, 별도 내부 확인란에 각 약속과 근거 메모를 표시하세요.
[고객 메일과 표를 붙여 넣으세요.]
```

## 메모와 대조할 수 있는 완성 예시
> 제목: CSV 내보내기 문제 관련 안내
>
> 문의해 주셔서 감사합니다. 오늘 오후 5시 회의에 자료가 필요하신 상황을 확인했습니다.
>
> 문의 내용은 기술팀에 전달해 조사를 요청했습니다. 현재 원인과 복구 시각이 확인되지 않아 회의 전 정상화 여부를 약속드리기는 어렵습니다. 추가 진전이 없더라도 오후 3시까지 현재 상황을 다시 안내드리겠습니다.
>
> 조사를 위해 문제가 발생한 시각, 사용 중인 브라우저와 버전, 표시되는 오류 메시지를 알려 주시겠어요? 조사에 필요하지 않은 개인정보나 업무 자료는 제외해 주세요.
>
> 이용에 불편을 드려 죄송합니다.

이 문장은 편집한 답장 예시입니다. 같은 프롬프트에서 항상 같은 문장이 나온다는 뜻은 아닙니다. 핵심 약속은 복구가 아닌 상황 안내입니다.

## 정중해도 사실이 바뀌었다면 수정합니다
| 초안의 문구 | 문제 | 고치는 방법 |
| 시스템 과부하가 원인입니다 | 원인은 미확인입니다 | 기술팀에 조사를 요청한 사실만 씁니다 |
| 오후 3시까지 복구하겠습니다 | 연락 시각을 복구 시각으로 바꿨습니다 | 오후 3시까지 상황을 안내한다고 씁니다 |
| 앱을 재설치해 주세요 | 검증된 해결 절차가 아닙니다 | 예정한 조사 정보만 질문합니다 |

추가 요청은 “두 번째 문단의 약속만 고쳐 주세요. 오후 3시는 상황 안내 시각이지 복구 시각이 아닙니다. 다른 사실은 바꾸지 마세요”처럼 차이를 지정합니다.

# ChatGPT로 견적 비교표 만들기: 인원과 필수 조건을 먼저 맞추기
회당 요금, 전체 요금, 인당 요금은 숫자만 나란히 놓아서는 비교할 수 없습니다. 같은 서비스를 제공하는 총액으로 계산한 뒤 필수 조건을 확인해야 합니다.

다음 교육 견적은 모두 가상 사례입니다. 금액은 계산 설명을 위한 일본 엔화이며 세금을 제외합니다. 실제 시세나 공급업체 추천이 아닙니다.

## 구매하려는 교육의 범위를 고정합니다
대상은 30명이고 예산은 450,000엔입니다. 10월 20일까지 교육을 마쳐야 하며, 교육 후 30일간 질문할 수 있어야 합니다.

| 견적 | 제공된 정보 |
| A | 회당 180,000엔, 정원 10명. 30명은 같은 교육을 3회 실시. 기한과 30일 질문 지원 확인. 추가 비용 없음. |
| B | 30명 전체 420,000엔. 기한과 30일 질문 지원 확인. 추가 비용 없음. |
| C | 인당 9,000엔과 초기 설정 60,000엔. 30명 지원. 실시일과 질문 지원 기간은 미기재. 그 밖의 요금은 기재되지 않음. |

A는 이번 인원 기준으로 180,000엔짜리 대안이 아닙니다. C에 정보가 없다고 질문 지원이 아예 없다고 판단해서도 안 됩니다.

## 필수 조건과 선호 조건을 분리해 요청합니다
```text
세 견적을 내부 선정 회의용으로 비교해 주세요.
필수 조건: 30명, 세금 제외 총액 450,000엔 이하, 10월 20일까지 완료, 교육 후 30일 질문 지원.
제공된 견적만 사실로 사용하세요.
30명 총액과 계산식을 표시하세요.
각 필수 조건을 충족, 미충족, 미확인으로 구분하세요.
누락된 정보를 0점 또는 기능 없음으로 처리하지 마세요.
현재 판단할 수 있는 후보와 추가 확인이 필요한 후보를 나누세요.
결정 전에 필요한 확인 질문도 작성하세요.
최저 금액 하나만으로 추천하지 마세요.
[견적을 붙여 넣으세요.]
```

## 계산까지 완료한 비교표
| 확인 항목 | A | B | C |
| 계산식 | 180,000 × 3 | 전체 420,000 | 9,000 × 30 + 60,000 |
| 총액, 엔·세금 제외 | 540,000 | 420,000 | 330,000 |
| 예산 이내 | 미충족 | 충족 | 충족 |
| 10월 20일까지 완료 | 확인 | 확인 | 미확인 |
| 30일 질문 지원 | 확인 | 확인 | 미확인 |
| 현재 판단 | 예산 초과 | 필수 조건 확인됨 | 기한과 지원 확인 후 판단 |

지금 모든 조건을 확인할 수 있는 곳은 B입니다. 그렇다고 B가 모든 면에서 가장 좋다는 뜻은 아닙니다. C도 조건을 확인하면 후보가 될 수 있습니다. 실제 업무에서는 계산을 별도로 점검하고 각 행에 견적 이름, 확인일, 근거 위치를 남기세요.

## 빈칸에서 공급업체에 보낼 질문을 만듭니다
> 30명 교육을 검토하고 있습니다. 10월 20일까지 완료할 수 있나요? 교육 후 30일간 참가자가 질문할 수 있나요? 두 조건이 가능하다면 제시된 총액 330,000엔에 포함되는지도 확인 부탁드립니다.

추가 비용이 생기면 지원 항목뿐 아니라 총액도 수정합니다. 결론만 바꾸고 오래된 계산을 남기면 다음 검토자가 다른 조건으로 판단하게 됩니다.

## 우선순위를 바꿔도 필수 조건은 유지합니다
```text
인원, 완료 기한, 30일 질문 지원은 필수로 유지하세요.
C가 이를 확인한 경우에만 적격 후보를 총액 우선으로 다시 비교하세요.
현재 미확인인 내용을 확인된 사실처럼 다루지 마세요.
어떤 새 정보가 결론을 바꾸었는지 설명하세요.
```

점수 평균이 필수 조건 위반을 가리지 않도록 합니다. 비교의 가치는 멋진 순위를 만드는 것보다 현재 자료로 어디까지 판단할 수 있는지 드러내는 데 있습니다.

## 비교 준비를 Prompt Ready로 반복합니다
재사용할 것은 “B를 선택한다”가 아니라 인원, 요금 단위, 필수 조건, 미확인 처리 방식입니다. 이를 Prompt Ready에서 정리하고 요청문을 확인한 뒤 AI에 붙여 넣습니다. 원본 견적 검증과 실제 구매 승인은 별도 업무입니다.

# 회의 메모를 할 일로 바꾸기: 담당자와 문의 대상을 바꾸지 않는 방법
메모에 이름이 있다고 그 사람이 담당자는 아닙니다. “다나카에게 물어보기”는 사토의 할 일일 수 있습니다. 결정, 제안, 취소, 미배정 사항을 분리한 뒤 후속 메일을 만드세요.

다음은 2026년 10월 5일의 가상 회의입니다. 결과표는 설명용으로 편집한 답안이며 실제 회의나 AI 처리 성능을 측정한 결과가 아닙니다.

## 여덟 줄에 서로 다른 정보가 섞여 있습니다
```text
M1: 제안서에 최신 가격표를 쓰기로 합의.
M2: 야마다가 10월 7일까지 서비스 후보 목록 공유.
M3: 데모 환경은 금요일까지 준비 가능할까? 먼저 환경 사용 가능 여부 확인 필요.
M4: 사토가 다나카에게 법무 상담이 가능한지 문의. 기한 미정.
M5: 고객은 다음 주 내부 검토 예정. 날짜는 아직 듣지 못함.
M6: 비교표 업데이트는 이번에는 불필요. 이전 요청 취소.
M7: 가격표 교체 담당자는 회의에서 정하지 않음.
M8: 고객 답변을 받은 뒤 다음 회의 날짜 결정.
```

M3의 금요일은 질문이지 확정 기한이 아닙니다. M5는 고객의 계획입니다. M6는 취소된 작업입니다. 모두를 우리 팀의 확정 할 일로 바꾸면 안 됩니다.

## 문장을 다듬기 전에 분류합니다
```text
메모를 결정 사항, 실행할 일, 확인할 사항, 취소한 작업으로 나누세요.
할 일의 항목: 작업, 담당자, 문의 대상, 기한, 근거 메모 번호.
이름만 보고 담당자를 추측하지 마세요.
질문을 확정 기한으로 바꾸거나 고객 계획을 우리 할 일로 만들지 마세요.

충돌하는 내용은 스스로 해결하지 말고 확인 사항으로 표시하세요.
[M1~M8을 붙여 넣으세요.]
```

## 원문으로 돌아갈 수 있는 결과
| 작업 | 담당자 | 문의 대상 | 기한 | 근거 |
| 서비스 후보 목록 공유 | 야마다 | 해당 없음 | 10월 7일 | M2 |
| 법무 상담 가능 여부 확인 | 사토 | 다나카 | 미정 | M4 |
| 제안서 가격표를 최신판으로 교체 | 미확인 | 미확인 | 미확인 | M1, M7 |

최신 가격표 사용은 합의됐지만 교체 담당은 미정입니다. 데모 환경의 가능 여부·담당·기한, 고객 내부 검토일, 다음 회의일은 확인 목록에 남깁니다. 비교표 업데이트는 M6에 근거해 취소 목록에 둡니다.

미확인 칸이 있다는 것이 추출 실패는 아닙니다. 사람에게 확인할 곳을 찾는 것이 이 단계의 완성입니다.

## 잘못된 행만 고칩니다
```text
M4에서 질문하는 담당자는 사토이고, 문의 대상은 다나카입니다.
해당 행의 두 항목만 고쳐 주세요. 다른 작업과 기한은 바꾸지 마세요.
```

AI가 데모 준비를 10월 9일까지라고 확정하면 M3는 질문이었다고 알려 주세요. 달력으로 금요일 날짜를 찾을 수는 있어도 없던 합의를 만들 수는 없습니다.

메모는 A의 조건 충족, B의 기한 초과, C의 확인 필요를 구분해야 합니다. 가격 열만 남기면 판단에 필요한 조건이 사라집니다.

## 각 창을 얼마나 조작하는지로 고릅니다
| 작업 방식 | 먼저 고려할 배치 | 이유 |
| 두 문서를 계속 편집 | 일반 창 나란히 배치 | 양쪽 조작 공간이 필요 |
| 메모 작성이 중심이고 몇 행만 참조 | 주 작업창과 작은 참고 화면 | 작성 영역을 넓게 유지 |
| 큰 그림이나 복잡한 표를 이해 | 큰 원본창 또는 분할 화면 | 작게 만드는 것보다 가독성이 우선 |

macOS에는 창 타일 배치와 Split View가 있습니다. 버전에 따라 조작이 달라지므로 [Apple 안내](https://support.apple.com/guide/mac-help/tile-app-windows-mchlef287e5d/mac)를 확인하세요. 참고 도구는 이런 배치를 보완하는 선택지이지 모든 경우의 대체품은 아닙니다.

## 제목과 조건을 함께 남깁니다
자료와 메모를 열고 Pocket Screen에서 참고할 원본창을 선택합니다. 필요한 행뿐 아니라 열 제목도 보이게 한 뒤 메모 작성으로 돌아갑니다. 참고 화면은 입력 중인 줄이나 중요한 버튼을 가리지 않는 곳에 둡니다.

계속 확대해야 읽힌다면 원자료에 더 큰 공간을 주세요. 가장 작은 창을 만드는 것이 목적이 아니라 문맥을 읽으며 불필요한 전환을 줄이는 것이 목적입니다.

## 실시간 정보와 멈춘 상태를 구분합니다
지금 상태를 확인해야 하면 실시간 참조가 적합합니다. 멈춘 화면은 비교 시점을 보존하지만 뒤에 바뀐 조건을 자동으로 반영하지 않습니다. 최종 판단 때는 원본으로 돌아가 최신 상태를 확인합니다.

브라우저창 하나의 데모가 모든 탭을 동시에 독립적으로 실시간 캡처한다는 증거는 아닙니다. 설치한 공개 버전의 기능을 확인하고 아직 공개되지 않은 데모 기능을 현재 기능으로 취급하지 마세요.

## 마지막 메모를 원자료와 대조합니다
> A는 납기 2주와 보증 1년을 충족한다. B는 보증이 길지만 납기를 지키지 못한다. C는 적격 후보로 비교하기 전에 납기와 보증을 확인해야 한다.

참고 화면은 정보 접근을 돕고 사실의 최신성이나 판단을 보증하지 않습니다. 화면 공유 전에는 무해한 자료로 수신 화면을 별도 확인하세요. 이 글은 배치 예시이며 시간 단축률이나 모든 환경의 공유 제외 성능을 측정한 자료가 아닙니다.

## 한 점과 관계를 다른 방식으로 보여 줍니다
포인터는 어떤 버튼인지, 범위는 어떤 행들이 설명에 포함되는지 알려 줍니다. 읽을 수 있는 글자와 목적 설명을 대신하지는 못합니다. 설정 하나를 말하며 화면 전체를 강조하면 대상이 오히려 흐려집니다.

Pointer Cue는 Mac에서 잠깐의 포인터·범위 강조를 더할 수 있습니다. 설치된 버전에 설정된 제스처를 사용하세요. 뒤에 다시 볼 화살표를 남겨야 한다면 그리기 도구가 다른 필요를 해결합니다.

## 조작 후 상태를 다시 확인해 줍니다
두 설정의 최종 상태를 말하고 화면을 잠깐 유지하세요. “보시다시피”보다 무엇이 달라졌는지 구체적입니다. 추가 강조 없이 한 번, 포인터나 범위를 더해 한 번 연습하고 대상과 결과를 찾을 수 있는지 비교하세요. 효과의 개수를 늘리는 것이 목적은 아닙니다.

## 시청자가 받는 화면도 확인합니다
실제 원격 시연에서는 무해한 자료로 참여자 화면을 확인합니다. 작은 글자나 가는 선은 캡처와 전송 후 다르게 보일 수 있습니다. 로컬 제품 영상이 수신 측 화질을 검증한 결과는 아닙니다.

웹사이트를 조작하는 제품 영상은 강조 원리의 예시이며 이 가상 설정 화면의 실행 기록은 아닙니다. 개발 중 영상 역시 공개 버전의 기능이나 제공 조건을 자동으로 증명하지 않습니다.

## 다음 시연에 적용합니다
기밀 없는 실제 작업 하나를 정하고 전후 상태를 적습니다. 강조가 정보를 더하는 위치 하나를 고른 뒤 변경 후 멈추는 구간을 연습하세요. Pointer Cue는 잠깐의 표식이 말에 도움을 줄 때 사용하고, 결과를 볼 때는 조용히 두어도 됩니다.
