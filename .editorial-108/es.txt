# Responder a un cliente con ChatGPT: hechos, compromisos y próxima actualización
El cliente necesita sus datos antes de una reunión, pero el equipo técnico aún no conoce la causa del fallo. Es posible dar una primera respuesta útil sin prometer una recuperación que nadie ha confirmado.

El correo, las notas internas y las respuestas de este artículo son un caso ficticio de formación. No son mensajes de un cliente real ni resultados registrados de una prueba de IA.

## Dos horas que significan cosas distintas
> La exportación CSV ya no genera un archivo. Necesito los datos hoy a las 17:00 para una reunión interna. ¿Estará resuelto para entonces? Por favor, informadme de la situación.

Las 17:00 son el plazo del cliente. Las 15:00 son, en este caso, la hora acordada internamente para dar noticias. Ninguna de ellas es una hora de recuperación confirmada.

| Tipo de información | Lo que sabe el equipo |
| Confirmado | Se ha recibido el aviso y se ha trasladado al equipo técnico para investigar. |
| Desconocido | Causa, usuarios afectados, hora de recuperación y alternativa que funcione. |
| Compromiso autorizado | Enviar una actualización antes de las 15:00, aunque no haya avances. |
| Datos que pedir | Hora del fallo, navegador y versión, posible mensaje de error. |
| Sin autorización | Reembolso, compensación, entrega manual de datos o plazo de reparación. |

## Delimitar lo que la IA puede redactar
Utiliza un entorno de IA autorizado para esa información. Quitar el nombre del cliente no elimina necesariamente el carácter confidencial de los datos.

```text

Reconoce que necesita los datos a las 17:00 y comunica el traslado al equipo técnico.
No prometas recuperación antes de las 17:00: la hora es desconocida.
Promete una actualización antes de las 15:00, incluso sin nuevos avances.
Pide la hora del fallo, el navegador y su versión, y cualquier mensaje de error.
No añadas causas, pasos de reparación, alternativas, reembolsos ni otros compromisos.
Devuelve asunto y cuerpo. Después, en una sección interna separada, enumera cada compromiso y la nota que lo autoriza.
[Pega el correo y la tabla.]
```

## Una respuesta coherente con las notas
> Asunto: Actualización sobre la exportación CSV
>
> Gracias por avisarnos. Entiendo que necesitas los datos para tu reunión de las 17:00.
>
> Hemos trasladado el aviso al equipo técnico para que lo investigue. La causa y la hora de recuperación todavía no están confirmadas, por lo que no puedo asegurar que la exportación vuelva a funcionar antes de tu reunión. Te enviaré una actualización antes de las 15:00, aunque todavía no haya novedades.
>
> ¿Podrías indicar cuándo ocurrió el fallo, qué navegador y versión utilizas, y si aparece algún mensaje de error? No incluyas datos personales o de negocio que no sean necesarios para investigar.
>
> Lamento las molestias que está causando el problema.

Es una respuesta de ejemplo editada para el artículo, no un texto que todos los modelos deban producir. Su compromiso es informar, no reparar.

## Corregir el error concreto
| Frase del borrador | Problema | Corrección |
| «La causa es una sobrecarga del sistema». | La causa no se conoce. | Indicar únicamente que se ha trasladado para investigación. |
| «Estará reparado a las 15:00». | Convierte una comunicación en una reparación. | «Te enviaré una actualización antes de las 15:00». |
| «Reinstala la aplicación». | Ese paso no se ha confirmado. | Pedir los datos de entorno previstos. |

Una instrucción útil sería: «Corrige solo el compromiso del segundo párrafo. Las 15:00 son la hora de actualización, no de recuperación. No cambies los demás hechos».

## Informar también cuando no hay avances
Si a las 15:00 solo se sabe que la investigación sigue, basta con: «Como acordamos, te informo de la situación. La investigación continúa, pero todavía no se han confirmado la causa ni la hora de recuperación». Añade otra hora de contacto solo después de acordarla internamente. La IA no debe inventar un plazo tranquilizador.

Abre la fuente y la nota. En Pocket Screen, elige la ventana que quieres consultar y mantén visibles las filas relevantes con sus encabezados. Vuelve a escribir. Coloca la referencia para que no cubra la línea actual o un control importante.

Si debes ampliarla continuamente, concede más espacio a la fuente. El objetivo no es la ventana más pequeña posible, sino un acceso legible al contexto con menos cambios innecesarios.

## Separar una referencia en vivo de un estado conservado
La vista en vivo sirve para información que debe seguir actualizándose. Una vista congelada conserva un estado y no incorpora automáticamente los cambios posteriores. Antes de decidir, vuelve a la fuente para comprobar si han cambiado condiciones.

Una demostración de una ventana de navegador no demuestra captura independiente y simultánea de todas sus pestañas. Utiliza solo los controles de la versión publicada instalada, sin tratar una demostración futura como función disponible hoy.

# Explicar una acción al compartir pantalla: un guion de 30 segundos
Mover el puntero no explica por qué importa un botón. Coordina frase, objetivo, operación y resultado para que el espectador no tenga que adivinar qué cambió.

La interfaz de práctica es ficticia: «Notificaciones inmediatas» y «Resumen semanal» están activados. Se debe desactivar solo la primera opción. Los tiempos son una pauta de ensayo, no un resultado experimental.

## Anunciar el resultado antes del clic
La idea no es «he hecho clic», sino «inmediatas desactivadas, resumen semanal conservado».

| Tiempo | Decir | Hacer | Señal |
| 0–5 s | «Quitaremos las inmediatas, pero conservaremos el resumen». | Mantener ambos controles visibles | Sin marca adicional |
| 5–10 s | «Este es el control de las notificaciones inmediatas». | Situar el puntero en etiqueta y control | Resaltado breve del puntero |
| 10–16 s | «Son ajustes independientes». | Mostrar las dos filas | Resaltar el área si aporta contexto |
| 16–22 s | «Desactivo solo este». | Pulsar una vez el primer interruptor | Mantener la acción visible y tranquila |
| 22–30 s | «Inmediatas desactivadas; semanal sigue activo». | Pausar en el resultado | No taparlo con otra animación |

## Un punto para un botón, un área para una relación
El puntero responde «¿qué botón?». El área responde «¿qué filas forman parte de la explicación?». Ninguna señal sustituye etiquetas legibles o una frase sobre el propósito. Resaltar toda la pantalla puede dificultar localizar una sola opción.

Pointer Cue puede añadir énfasis temporal al puntero o a un área en Mac. Usa el gesto configurado en la versión instalada. Si necesitas dejar una flecha para consultarla después, una herramienta de dibujo resuelve otra necesidad.

## Confirmar el estado después de operar
Nombra ambos estados finales y deja un momento para verlos. Es más concreto que «como podéis ver». Ensaya una vez sin señales y otra con una señal puntual o de área. Comprueba si se identifican objetivo y resultado, no cuántos efectos aparecen.

## Revisar lo que recibe el participante
En una demostración remota, comprueba la vista recibida usando contenido sin riesgo. El texto pequeño y las líneas sutiles pueden verse distintos tras captura y transmisión. Un vídeo local del producto no es una prueba de calidad del receptor.

Un clip que opera sobre una web ilustra el tipo de énfasis, no la ejecución de este ejercicio ficticio. Tampoco debe utilizarse una preversión para prometer funciones o condiciones de la versión publicada.

## Preparar tu próxima demostración
Elige una sola tarea real sin información confidencial. Anota estado inicial y final, selecciona un lugar donde la señal aporte orientación y ensaya la pausa posterior. Usa Pointer Cue cuando el énfasis temporal ayude a la frase; deja que el resultado quede visible por sí mismo.
