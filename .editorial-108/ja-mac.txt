# MacBookの1画面で資料を見ながら作業する｜同じ比較メモで配置を選ぶ
資料を見返すたびに作業中の画面を切り替えているなら、必要な部分だけ参照として残す方法があります。資料全体に半分の画面を渡すか、小さな参照を置くかは、両方をどれくらい操作するかで選びます。

以下は自作の仕様表から判断メモを書く例です。実際の見積もり、時間短縮の実測、製品の性能比較ではありません。

## 仕様表と、書くべきメモを先に決める
部品を2週間以内に受け取り、1年以上の保証が必要だとします。価格は実在しない比較用の単位です。

| 候補 | 納期 | 仮の価格 | 保証 |
| A | 2週間 | 120 | 1年 |
| B | 3週間 | 100 | 2年 |
| C | 未確認 | 90 | 未確認 |

作るメモは、Aが二条件を満たし、Bが納期を外れ、Cは確認が必要、と分かる短い文章です。価格だけを小さく残すと、安い候補を選ぶだけになりかねません。必要なのは列名と条件が読める範囲です。

## 同じ仕事で、三つの配置を比較する
| 作業の特徴 | 最初に考える配置 | 向く理由 |
| 原表とメモの両方を頻繁に編集 | 通常のウィンドウを並べる | 両方の操作欄を大きく取れる |
| メモを書くのが中心で、資料の数行だけ確認 | 主画面と小さな参照ビュー | 主作業の面積を残せる |
| 大きな図や密集した表全体の理解が必要 | 原表を大きく表示、または分割 | 小ささより可読性と文脈が重要 |

macOSにはウィンドウのタイル表示やSplit Viewがあります。操作は利用するOSによって異なるため、[Appleのウィンドウ配置の案内](https://support.apple.com/guide/mac-help/tile-app-windows-mchlef287e5d/mac)を参照してください。参照ビューは標準機能を補う選択肢で、すべての仕事で置き換える必要はありません。

## 小窓に残すのは、ウィンドウ全体ではなく判断に必要な部分
原資料とメモを開き、Pocket Screenで参照元のウィンドウを選びます。対象の行と列名を読める状態にし、メモの入力欄を隠さない位置へ置きます。参照が小さすぎて何度も拡大するなら、無理に隅へ押し込まず原資料の面積を増やします。

{{MEDIA:PS-CURRENT}}

画像は公開済みの製品資料から、参照表示の考え方を確認するためのものです。今回のA・B・Cの表を実行した画面や、作業時間を測った結果ではありません。

この使い方で残したいのは「目の前にあるすべての画面」ではなく、いま書く文章の根拠です。主画面では操作を続け、必要な部分だけ見返せることに価値があります。

## 更新を追う参照と、その時点を残す表示は区別する
最新状態を追いたい資料にはライブ参照、比較のために状態を残したい場面には固定した表示、という使い分けがあります。固定した表示は、その後に元資料が変わっても同じ状態のままなので、最終確認では原資料へ戻ります。利用する機能と操作はインストール済みの公開版で確認してください。

同じブラウザーウィンドウを切り替えたデモを、すべてのタブを独立して同時にライブ取得していると読み替えないことも重要です。複数の見え方と、複数の独立したライブ取得は別です。

## 完成したメモを原表と照合する
> Aは納期2週間と保証1年の条件を満たす。Bは保証が長いが納期条件を満たさない。Cは納期と保証の確認が必要なので、その回答後に適格な候補として比較する。

見た目が整ったメモでも、Cの未確認を「保証なし」と変えていないか、固定した古い表を使っていないかを確かめます。参照ビューは情報へ戻る手間を助けますが、情報や判断の正しさを保証するものではありません。

## 画面共有の前には、配置とは別の確認をする
手元で見える配置と、相手が受け取る画面は分けて確認します。共有する方式で無害なテスト内容を映し、参加者側でどう見えるか点検してください。共有除外の確認記事では、その手順と記録欄を扱います。

今回の配置が合うかは、同じ資料とメモを使い、両方を操作する頻度、文字の読みやすさ、入力欄への重なりで判断します。「小窓なら必ず速い」という結論を先に置かない選び方です。

# PiPが画面共有や録画に映るか確認する｜手元と出力を分けるテスト手順
自分のMacで小窓が見えていることと、相手の画面や録画にその小窓が入ることは、別々に確かめる必要があります。設定をオンにした画面だけでは、出力結果を確認したことになりません。

この記事は、無害なテスト内容と記録用の表を使う確認手順です。今回新たにすべての環境を実測した結果や、どの会議サービスでも必ず除外できるという保証は示していません。

## 本番のメモではなく「TEST」で始める
参照元に「TEST：参照ビューの確認」だけを表示します。パスワード、顧客情報、秘密鍵は使いません。Pocket Screenの参照表示と、インストールした版にある画面キャプチャ除外設定を確認します。

MacとmacOS、Pocket Screen、会議アプリまたはブラウザーの版を記録してから始めます。設定の場所を示す画像と、相手側で見えなかった記録は別の資料です。前者だけで後者を判断しないでください。

## 四つの出力を、それぞれ確かめる
| 出力 | すること | 実際に見る場所 |
| macOSのスクリーンショット | TEST参照を手元に表示したまま撮る | 保存された画像を開く |
| macOSの画面収録 | 参照を表示して短い操作を録る | 完成した録画ファイルを再生する |
| 会議の画面全体共有 | 実際に使うディスプレイを共有する | 別端末または参加者の受信画面 |
| 会議のウィンドウ共有 | 対象アプリのウィンドウへ切り替える | その方式の受信画面を別に確認 |

Zoom、Google Meet等では、画面全体・ウィンドウ・タブを同じものとして扱いません。使った方式と対象を記録します。macOSの収録操作は[Appleの案内](https://support.apple.com/en-us/102618)、Pocket Screenの設定は[公式サポート](https://labs.toybird.com/apps/pocket-screen/support.html)で現在の情報を確認できます。

## 結果欄は、確認できるまで埋めない
| 記録項目 | 書く内容 |
| 確認日時 | 実際にテストした日時 |
| Mac・OS | 機種とmacOSの版 |
| Pocket Screen | 版と関連設定の状態 |
| 共有・収録アプリ | アプリまたはブラウザーの版 |
| 共有対象 | 画面全体・ウィンドウ・タブと対象名 |
| 手元のTEST | 見える／見えない |
| 保存物または受信側のTEST | 見える／見えない／未確認 |
| 前回からの変更 | OS更新、方式、ディスプレイ変更など |

これは空の記録様式です。別端末が用意できなければ受信側は「未確認」で、予想だけで「見えない」にしません。一つのスクリーンショットが合格でも、会議の画面全体共有まで確認済みとは数えません。

## 共有途中の変更は、再確認のきっかけにする
画面全体からウィンドウへ切り替えた、別のモニターへ移した、アプリを更新した、といった変更があれば、該当する経路を再度点検します。同じ設定名でも、受け取る結果は実際の方式で確認します。

重要な会議では、最初に小さなTESTだけでリハーサルします。手元のプレビューを眺めるより、送った先の画面や保存されたファイルを開く方が、確認したいことに直接対応します。

## 相手に見えていたら、先に表示を止める
本番中に小窓が見えた場合は、共有停止や参照の非表示を先に行い、その後に設定・共有対象・別の録画ソフト・直前の更新を調べます。再起動や作り直しが必ず解決すると決め付けません。

確認できない環境では、非公開メモを共有対象の外や別端末に置くなど、実際に検証できる方法へ切り替えます。問い合わせには無害なTESTと版・再現手順を添え、機密を含む録画を送らないようにします。

## 除外機能は、秘密情報を置いてよい境界ではない
共有をしやすくする設定と、秘密情報を守る仕組みは同一ではありません。通知、別の収録経路、ソフトウェアの変更は、この表で確認していない露出を作る可能性があります。

Pocket Screenの参照を使う場合も、情報を必要最小限にし、実際に送る出力を確かめる習慣を優先します。記事の完成物は「必ず映らない」という宣言ではなく、自分の環境で何を確認し、何が未確認か分かる記録です。

# 画面共有で見る場所を伝える｜発話と操作を合わせる30秒の台本
マウスポインターが動いているだけでは、なぜそのボタンを見てほしいか伝わりません。目的を言い、位置を示し、操作し、結果を確認する順にすると、視聴者が変化を追いやすい説明になります。

ここでは「即時通知」と「週間サマリー」が両方オンの仮の設定画面を使います。即時通知だけをオフにする練習です。30秒という時間は台本の目安で、最適な時間を実測した数字ではありません。

## 操作の前に、残すものと変えるものを言う
伝えたい結果は「クリックしました」ではなく、「即時はオフ、週間はオンのまま」です。これを決めると、近くにある別の設定を次々に見せる必要がなくなります。

| 時間 | 話す内容 | 操作 | 強調の役割 |
| 0〜5秒 | 即時通知を止め、週間サマリーは残します | 両方の設定を見せる | まだ追加表示しない |
| 5〜10秒 | こちらが即時通知の設定です | 対象の名前とスイッチへポインターを置く | 一点を短く示す |
| 10〜16秒 | 二つは独立した設定です | 二行の関係を説明する | 必要なら範囲を囲む |
| 16〜22秒 | この一つだけをオフにします | 即時通知を一回クリック | 操作した場所を見失わせない |
| 22〜30秒 | 即時はオフ、週間はオンのままです | 結果の画面で止める | 新しい効果を重ねない |

{{DEMO:NOTIFICATIONS}}

この練習画面は記事内に作ったものです。Pointer Cueの実行画面や、機能を模倣するアプリではありません。スイッチを操作して、前後の状態をどの言葉で説明するか確かめられます。

## 一点・範囲・操作は、別々の情報を伝える
一点の強調は「どのボタンか」、範囲は「どの項目がこの説明に含まれるか」を示します。クリック後は、操作位置だけでなく結果を言います。強調の数を増やすのではなく、発話に足りない情報を補う考え方です。

{{MEDIA:PC-RANGE}}

提供された製品デモから、範囲を示す場面を静止画として使っています。実際の映像はWebページ上の操作で、上の通知設定を実行した記録ではありません。また、受信側の圧縮後の視認性を検証した資料でもありません。

## 普段の操作に、必要なときだけ目印を添える
Pointer CueはMacのポインターや一時的な範囲の強調に使えます。インストールした公開版で有効な機能と、設定済みのジェスチャーを使ってください。長く残す図や説明用の矢印が必要なら、描画ツールを使う場面もあります。

画面の文字が小さすぎるときに、ポインターだけ大きくしても問題は解決しません。共有範囲・アプリの拡大・表示する情報量を調整してから、どこへ目印を置くか決めます。

## 「見て分かるはず」で終わらせない
操作後に二つの状態を言い直し、短く止めます。「ご覧のとおり」だけより、途中から見た人や小さな画面で見ている人も結果へ戻れます。

同じ台本を、強調なしと、一点または範囲の強調ありで一回ずつ練習します。違いを比べるのは対象と結果を確認できるかで、どちらが必ず速い・全員に見やすいという実測評価はここでは行いません。

## リモート会議では、受信画面を確認する
本番と同じ共有方法で、機密を含まない素材を使い、参加者側の文字と線を確認します。ローカルでは見えた細い線や小さな文字が、伝送後も同じように見えるとは限りません。OS、会議アプリ、共有対象を変えた場合は、その条件で確認します。

# ScreenBrushとPointer Cueを用途で比較｜描き残す説明と、一時的に示す説明
ボタンを案内したいのか、数行の関係を示したいのか、後で見返せる矢印を残したいのか。同じ「画面を説明する」でも必要な道具は異なります。同じ三課題から比較します。

Toybird LabsはPointer Cueの提供者です。以下は公式の機能案内と提供デモを基にした用途の整理で、同一環境で両製品の操作時間や視認性を測定した結果ではありません。

## ScreenBrushを「描くことしかできないツール」と扱わない
ScreenBrushの[Mac App Storeの公式説明](https://apps.apple.com/jp/app/screenbrush/id1233965871)には、描画のほか、レーザーポインター、Cursor Halo、Flashlightなどの案内があります。描画のスナップショットを保存・再利用し、画像等へ書き出す機能も説明されています。

したがって「ポインターを示すならScreenBrushでは不可能」とする比較は正確ではありません。必要な表示が一時的か、残す注釈か、説明後にも編集や再利用をするかで考えます。

## 三つの課題を同じ基準で見る
| 課題 | ScreenBrushで確認する機能 | Pointer Cueで使う考え方 |
| A：ひとつの設定ボタンを案内 | レーザーポインターやCursor Halo等 | 普段の操作に一時的なポインター強調を添える |
| B：表の数行をひとかたまりとして説明 | 形状描画や範囲を照らす機能等 | 一時的な範囲強調で、説明中の行を示す |
| C：複数の矢印と説明を残して後で再利用 | 描画、編集、スナップショット | 一時的なCueだけで持続的な注釈の代わりにはしない |

上の表は同等機能の完全な一覧ではありません。どの操作をしたいか決め、現在の公開版の設定・利用条件を確認する入口です。価格やProの条件を古い版のまま一般化しません。

## AとBは、説明の直後に操作へ戻る場面
例えば設定変更を見せるときは、目的を言い、対象を示し、クリックし、変わった状態を確認します。表を読むときは「この三行」とまとめて示し、読み終えたら目印を残さず次へ進みます。

{{MEDIA:PC-RANGE}}

この静止画はPointer Cueの提供デモで範囲を示した場面です。ScreenBrushと同じ課題を並行操作した比較映像や、最新のあらゆる環境での描画を保証するものではありません。

Pointer Cueの使いどころは、描画作品をつくるのではなく、通常の操作説明中に必要な場所を示すことです。一方、使い慣れたScreenBrushのポインター機能で目的が足りるなら、必ず別ツールへ変える必要はありません。

## Cでは、説明を残すこと自体が成果物になる
矢印を三本引いて手順番号や説明を加え、後で同じ注釈を使いたい。その場合は「今どこを見るか」だけでなく、描いたものの編集・保存・再利用が重要です。こうした仕事ではScreenBrushの該当機能を確認する意味があります。

一時的な枠が消えることは、操作説明では利点になり得ますが、注釈の保存では目的に合いません。表示が残るか消えるかを、いつも長所・短所のどちらかと決めない比較です。

## 自分で比べるための記録欄
| 確認項目 | 記録すること |
| 共通の課題 | 同じ設定ボタン、同じ三行、同じ注釈を使ったか |
| 起動・設定 | インストール版、機能を有効にした設定 |
| 通常操作への復帰 | 次のクリックや入力へ無理なく戻れたか |
| 表示の持続 | 必要な間だけ見え、不要な間は消えるか |
| 再利用 | 後で使いたい表示を保存・編集できるか |
| 受信側 | 本番の共有方法で相手側を確認したか |

記録していない項目を、最速・軽い・必ず見やすいと書かないようにします。製品の違いより先に自分の完成物を決めれば、必要な比較項目が減ります。

通常の操作中に一時的に注目箇所を示したいならPointer Cue、図や注釈を描いて残したいならその機能を備える道具、という役割から試してください。両方の機能が重なる部分は、いつもの説明の流れで使いやすい方を選ぶのが現実的です。
