Check Whether a Reference View Appears in Screenshots and Screen Sharing

Keep a reference beside the material you are presenting. Set up Pocket Screen's capture exclusion and show/hide shortcut, then check what a participant receives through the sharing method you actually use.

This guide provides a reproducible check and an empty record template. It does not present new measurements or imply that one successful screenshot proves every meeting application will behave the same way.

Reference View case

Keeping reference information visible creates a second question: what appears in screenshots, recordings and the receiver’s shared screen? This article treats that output boundary as part of the Reference View workflow.

See the Reference View framework

Prepare a harmless reference first

Put “TEST: reference view” in the source and create a Pocket Screen view. Use this harmless content to try the layout you would use in a meeting.

  1. Choose capture exclusion: on macOS 26 or later, enable “Exclude PiP from Screen Capture” in Settings to exclude the view from supported screenshots, recordings and screen sharing. It is off by default. Enabling it does not guarantee the same result in every capture application.
  2. Know how to hide the views: the default shortcut for showing or hiding all views is Shift + Option + Command + P. If you saved a Custom binding in v2.1, use that binding. A Stream Deck profile must send the same shortcut as the app.
  3. Inspect the actual output: select the sharing target you will use in the meeting and check the receiving device. If you plan to record, inspect the saved recording too. Choose the relevant methods from the table below; you do not need to test output paths you will not use.

Record the result with the Mac, macOS, Pocket Screen and meeting-app or browser versions. A setting screenshot documents the setup; the receiving device or saved file documents the output.

Run each output path separately

Output What to do What to inspect
macOS screenshot Capture while the TEST reference is visible locally Open the saved image, not just its thumbnail
macOS recording Record a short interaction with the TEST view present Play the finished recording
Meeting: entire display Share the selected display in a test meeting Inspect the receiving device or participant's view
Meeting: one window Switch to the intended application window Inspect that mode separately on the receiver

For Zoom and Google Meet, record the precise mode used. A tab, window and entire display are not interchangeable test cases. Apple's screen-recording instructions and the meeting provider's current help can identify the controls in your environment.

Use a record that permits “not checked”

Field Record this
Date and time Your actual test time

Leave a result as not checked if you could not observe it. Do not fill it with an expected outcome. This is a template for your own environment, not a prefilled certification table.

Recheck at the points that change the result

If you switch from a window to a whole display, move to another monitor, replace the source, or update the software, repeat the relevant check. Do not assume an earlier result transfers unchanged. For an important meeting, a brief rehearsal with a second device is more informative than a setting that merely looks correct.

If the reference is visible to the receiver

If the participant can see the reference, use the show/hide-all shortcut or stop sharing first. The default is Shift + Option + Command + P; use your saved assignment if you chose Custom. Then check capture exclusion, the selected sharing target, other recording software and any recent updates.

If exclusion cannot be confirmed in the environment you need, keep private notes outside the shared target or on a separate device. Send support the harmless TEST example, versions and reproduction steps so the issue can be described without sharing private content.

Exclusion is a convenience, not a security boundary

Reference-view exclusion can support a presentation workflow, but it is not permission to display passwords or secret keys. Notifications, another recording path or a change in software can create different exposure. The reliable habit is to minimize sensitive material and verify the output you are actually sending.
